# 引継ぎメモ（handoff）

セッションをまたぐ**揮発的な引継ぎメモ**。**このファイルは毎回上書き**（最新1件だけを保持する）。
過去の失敗の蓄積は `docs/failures.md`（append-only・消さない）を見る。

## ①今回実施

**同梱見本（家計簿アプリ）を捨てて、リフォーム見積アプリの土台を作った（フェーズ0）。**

作るものの調査を先に行い、根拠のある土台を敷いた。

- **見積書の様式**：独自様式を作らず、**住宅リフォーム推進協議会「住宅リフォーム工事 御見積書」
  書式Ⅳ-1** に合わせる。PDF の実物から、集計欄の文言（「工事価格 （税抜き）／取引に係る消費税等／
  合計 （税込）」）、摘要（仕様）が独立列であること、明細末尾に「解体・廃棄物処理費」が
  印字済みであること、有効期限欄があることを確認した。
  https://www.j-reform.com/publish/pdf_shosiki/mitumori.pdf
  協議会様式が1列にまとめている「（単価・数量・時間 等）」だけ、計算できるよう
  **数量／単位／単価**の3列に分解している。
- **業界標準が無いと確認できたもの**：諸経費率（出典ごとに 5〜10% / 8〜22% / 30%超と割れる）、
  見積の有効期限日数（法令根拠なし）。**既定値をコードに埋めていない。**
- **UX**：NN/g の調査で「50歳と30歳で別のユーザビリティガイドラインを用意する必要はない」と
  結論が出ている。特別なシニア向けUIではなく **WCAG AA を満たした普通に良いUI**を土台にし、
  老視（40〜45歳開始・55歳で調節力喪失）を踏まえて視認性だけ上に振った。
  数値は `apps/web/app/globals.css` に集約（本文16px以上、入力欄16px以上＝iOS の自動ズーム防止、
  line-height 1.6、タップ対象48px以上）。

作ったもの:

- `apps/web/lib/calc.ts` … 見積の金額計算。画面・PDF・API はここだけを通す。
  計算順序を協議会様式に合わせて固定（明細→直接工事費小計→諸経費→値引き→工事価格（税抜）→
  消費税→合計（税込））。金額は整数（円）。端数は円未満切り捨て（負数は0方向＝`Math.trunc`）。
  消費税は税区分ごとに積み上げてから**1回だけ**端数処理する。
- `apps/web/lib/auth/` … 仮の認証。HMAC-SHA256 で署名した Cookie セッション。
  `session.ts`（発行・検証）/ `credentials.ts`（照合）/ `compare.ts`（時間依存しない比較）/
  `server.ts`（サーバーコンポーネント用の入口）。**本番の Supabase Auth への差し替えは
  この配下だけで済む。**
- `apps/web/proxy.ts` … Next.js 16 の proxy（旧 middleware）。ログイン要求と、
  リクエストごとの nonce 付き CSP を付ける。
- `apps/web/lib/security/csp.ts` … CSP の組み立て。`script-src` に `'unsafe-inline'` を入れず、
  nonce + `'strict-dynamic'` にしている。
- PWA … `app/manifest.ts` / `public/sw.js` / `public/icon-*.png`（依存を足さず自前生成）。
  サービスワーカーは**アプリの殻だけ**キャッシュする。金額データはキャッシュしない
  （古い数字を新しい数字と誤認する事故を避けるため）。
- `scripts/smoke.sh` … 受け入れ条件を HTTP で機械判定する。CI と手元で同じものを実行する。

テスト 49 件（`lib/calc.ts` 26 / セッション 12 / 照合 7 / 画面 3 / 疎通 1）。
スモーク 26 項目。`max-lines: 300` は 301 行のファイルを作って**実際に赤くなることを確認**した
（確認後に削除）。

## ②今回トラブル

3件とも `docs/failures.md` に記録済み。要点だけ:

- **`brace-expansion` の override が破壊的メジャーまで巻き上げて eslint が起動不能**になっていた。
  override を外したら脆弱性修正版（1.1.18）に自然解決し、監査も緑。テンプレート由来の地雷。

  `setsid` でプロセスグループごと止める形に直した。

## ③次回やる事

**まず、こちらの作業待ちが2つある。これが済むまでフェーズ1の一部が進まない。**

1. **Supabase プロジェクトを作り、URL と anon key を渡す**（service role key はサーバー専用の
   環境変数として別途）。本番でもそのまま使う土台なので、最初からこれで組む。
2. **Vercel に接続する。** 接続後、`.github/workflows/prod-smoke.yml` の 2 箇所を直す
   （`PROD_URL` を実際の割当ドメインに / `on:` に `push: branches: ["**"]` を戻す）。
   今は検査する本番URLが存在しないため `workflow_dispatch` だけにしてある。
   Vercel の環境変数に `AUTH_SECRET` / `DEMO_USER_EMAIL` / `DEMO_USER_PASSWORD` を入れる
   （`apps/web/.env.example` 参照）。

**フェーズ1（見積が作れて PDF が出る）**

- Supabase のスキーマとマイグレーション（顧客・案件・見積・見積明細・単価マスタ）。全テーブル RLS 有効
- 案件の CRUD、見積エディタ（明細の追加・並べ替え・階層・合計のリアルタイム表示）
- 単価マスタ（リフォームは**材工共の複合単価**が基本形）
- pdfme で協議会様式の PDF 出力。日本語フォントはサブセット化して埋め込む
- 受け入れ条件：明細20行で合計と消費税が電卓と一致 / PDF が文字化けせず改ページする /
  集計欄の文言が協議会様式どおり

**その後**：フェーズ2（写真：OS標準カメラ→合否→箇所タグ→明細紐づけ、EXIF回転は圧縮の**後**に
canvas で焼き込む）、フェーズ3（下請リンク `/q/[token]`：売価・掛率・原価・顧客名を
**返す経路をコードに存在させない**、自動テストで禁止キーの不在を検査）、
フェーズ4（UX 15項目の実測確認と通し確認）。

- 既存の見積書（Excel/PDF）の現物。協議会様式で着手はできるが、最終的な様式合わせに要る

- 本番で実在の顧客情報を扱うときの社外ホスティング可否

公開（Public 化と branch protection）をするなら `setup` の手順7。
