# 引継ぎメモ（handoff）

セッションをまたぐ**揮発的な引継ぎメモ**。**このファイルは毎回上書き**（最新1件だけを保持する）。

- 製品の定義（誰が使うか・差別化点・書類の仕様・作り直しの設計）→ `docs/design.md`
- **実装の受け入れ条件・テスト方針・デバッグ方針・PRの区切り** → `docs/plan-rebuild.md`
- 過去の失敗の蓄積 → `docs/failures.md`（append-only・消さない）
- 開発の進め方・規約 → `AGENTS.md`

`docs/plan-rebuild.md` と食い違ったときに、次のセッションが古い仕様を実装してしまう。

## ⑤分かっているが直していないこと

- **`lib/db/` の一覧系が、1000件を超えた分を黙って落とす**（PostgREST の既定の上限。
  アプリ側で範囲を指定していない）。`projects` と `subcontractors` は対策済みだが、
  `listPriceMasterForOwner` / `listQuoteGroupResponsesForRequests` / `listPhotosForProject`
  などは未対策。利用者からは「登録したのに出てこない」に見える。
- `seedDemoData` は複数の insert を分けて投げるので、途中で失敗すると中途半端な行が残る
  （CodeRabbit の指摘）。1つのトランザクション（DB関数）に寄せると直る。
  デモは作り直しが効くので範囲外にした。
- **デモの入口が、ログイン中の実利用者のセッションを黙って上書きする**（デモボタンを押すと
  その場でログアウトされる）。他サイトからは強制できない（`isSameOrigin` が 403 で止める）。
  トップにデモボタンを常に出すのは意図した仕様なので、直すなら出し方の判断から。
- **旧経路 `/q/<token>` の単価欄が小数を通す。** クライアント検証は有限数なら通し、サーバが
  `Number.isInteger` で弾く。押せるのに必ず失敗する入力が通る（データは壊れない）。
- **`newPhotoStoragePath` が WebP を `.jpg` として保存する。** `contentType` は正しく渡すので
  表示は壊れない。`docs/design.md` 7章の「WebPはJPEGへ正規化する」は未実施
  （いま PDF に写真を埋め込む経路が無いため実害は出ていない）。
- `docs/failures.md` の append-only を機械で止めていない（2回破りかけている）。
- **squash マージ後にブランチを作り直す規則を、機械で止めていない**（4回違反している）。
- `auto-merge.yml` がイベントを取りこぼすと、全緑のPRが誰にも気づかれず止まる
  （塞ぎ方の候補は `docs/failures.md` 2026-08-06 に書いた）。
