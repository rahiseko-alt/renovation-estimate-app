## ①今回実施

**フェーズ1（見積が作れる）に着手し、案件登録と見積エディタを PR #7 に追加した。**
Supabase がまだ無いため `lib/db/` に仮の永続化層を置き、DB接続の差し替えに備えた設計にしている。

- 「まずは仮で良い」の了承のもと、諸経費率デフォルト・有効期限日数・既存見積書様式の
  3つの未確定事項をブロッカーにせず、既存の設計（諸経費率は既定値なし・協議会様式）のまま
  フェーズ1の実装を進めた。
- 追加した画面：`/projects/new`（案件登録）、`/projects/[id]`（詳細）、
  `/projects/[id]/estimate`（見積エディタ本体）。エディタは `calc.ts` をそのまま呼んで
  工事価格・消費税・合計をリアルタイム表示する。既定行として「解体・廃棄物処理費」を
  協議会様式どおり自動で立てる。
- `lib/db/`（仮のメモリ実装。サーバープロセス再起動で消える。Supabase 接続時はこの配下だけ
  差し替えれば済む構造）と、その単体テストを追加。
- Playwright（`/opt/pw-browsers` の Chromium、リポジトリには未導入・スクラッチ実行のみ）で
  実ブラウザ操作を都度確認しながら実装した。

**CodeRabbit のレビューで3件の指摘を受け、すべて修正した：**

1. `saveEstimateAction()`（Server Action）がログイン状態・案件の存在・入力の妥当性を
   検証していなかった。ページ表示時の確認だけでは Server Action という別の更新入口を
   保護できないという指摘。`getCurrentUser()` / `getProject()` / `calcEstimate()` を
   保存前に通す形に直した（コミット `fb7c6c3`）。
2. 数量・単価が数値として読めない入力（"abc" 等）や、諸経費率の空欄・非数値入力を、
   計算・保存から**無言で**除外していた（削除ではなく黙って消える形になっていた）。
   該当欄を赤枠＋インラインエラーで示し、合計欄も説明に置き換え、保存ボタンを
   無効化するように直した（コミット `cff422f`）。
3. 上記2の修正が手元の Playwright 確認のみで、リポジトリにコミットされた自動回帰テストが
   無いという指摘（Low）。判定ロジック（`isValidNumberInput`）を
   `lib/estimateLineValidation.ts` に切り出して Vitest で単体テストした。ただし
   「入力するとボタンが実際に無効化されるか」という DOM 配線までの自動テストは、
   Testing Library か Playwright のブラウザ実行が要る規模の判断だと考え、1件の Low
   指摘のために場当たり的に導入しない、とその場で判断して見送った（コミット `133e38b`）。
   CodeRabbit もこの判断に同意し、学習として記録された。

**現在の状態**：CI（`quality`/`smoke`/`ci-green`、CodeQL）は最新コミット `133e38b` で全部緑。
PR #7 の全9スレッドが解決済み。CodeRabbit の指摘は残っていない。PR はまだドラフトのまま
（マージ・公開のPR化は指示されていないので手を付けていない）。
