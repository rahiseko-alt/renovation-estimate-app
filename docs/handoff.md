# 引継ぎメモ（handoff）

セッションをまたぐ**揮発的な引継ぎメモ**。**このファイルは毎回上書き**（最新1件だけを保持する）。

- 製品の定義（誰が使うか・差別化点・書類の仕様・作り直しの設計）→ `docs/design.md`
- **実装の受け入れ条件・テスト方針・デバッグ方針・PRの区切り** → `docs/plan-rebuild.md`
- 過去の失敗の蓄積 → `docs/failures.md`（append-only・消さない）
- 開発の進め方・規約 → `AGENTS.md`

**恒久的な決定をこのファイルに書かない。** 上書きされて消えるうえ、`docs/design.md` /
`docs/plan-rebuild.md` と食い違ったときに、次のセッションが古い仕様を実装してしまう。

## ③次回やる事

**クライアントからのフィードバック対応が最優先。** 何を言われたかを聞いてから動く。
以下は、来なかった場合の続き。

1. **資料の写真の差し替え。** 実物の現場写真4枚（内装＝壁紙／外壁＝タイル／
   給排水＝配管／解体＝廃材）を書類の枠に入れて 9枚目を撮り直す。
   **資料そのものが消えているので、作り直しからになる。**
2. **19枚目の連絡先**を利用者から聞いて入れる（または枚ごと落とす）。
3. **実機のスマホでデモを踏んでもらう。** とくに**カメラ経路**。
   E2E は「写真なしで進む」側しか通せない（実ブラウザでカメラを扱えない）ので、
   **そこだけ機械で見られていない。**
4. **下請けへの依頼の受け渡しが未実装**（メール送信もリンクの表示も無い）。
   資料でも「ここは最優先で作ります」と言っている。実装するなら次はここ。
5. **短いURLを使えるようにするか**（利用者の作業）。`renovation-estimate-app.vercel.app`
   （`-web` 無し）は 404。商談で口頭で伝えると必ず間違える。
   Vercel の Project → Settings → Domains で追加できる。
6. デモの入口の流量制限、期限切れデモの定時削除、社印の扱い（いずれも未決）。

## ④まだ埋まっていない前提

- 依頼提示後に写真を追加したときの扱い（法的評価は未確認）
- 期限を過ぎた回答の扱い
- 諸経費率の実際の数字、見積有効期限の日数（デモ用に決め打ちでよい）
- **明細ごとに別の掛率を持たせるか**（採用の掛率そのものは 1 に決めた。`docs/design.md` 7章）
- 本番で実在の顧客情報を扱うときの社外ホスティング可否
- **法定③（設計図書＝写真＋数量）の充足判定条件**（未決）。
  **送信ゲートは③を検査していない**（`lib/db/submissionGate.ts` が見るのは
  法定④⑤⑥⑧の9スロットと⑦の12区分だけ）。写真が0枚・数量が全部0でも送信できる。
  実運用に出す前に、充足条件を一次情報から決めて判定とテストを足すこと。
- **背景の挿絵の権利関係**。利用者から受け取ったものをそのまま使っている。
  出所と利用条件は確認していない（`AGENTS.md` 公開前提5）。

## ⑤分かっているが直していないこと

- **`docs/flows.md` の表と実装の一致を、機械で見ていない箇所がある。**
  D7 は E2E と本番検査の両方で見るようにしたが、他の画面は文言の grep どまり。
- `seedDemoData` は複数の insert を分けて投げるので、途中で失敗すると中途半端な行が残る
  （CodeRabbit の指摘）。1つのトランザクション（DB関数）に寄せると直る。
  デモは作り直しが効くので範囲外にした。
- **`lib/db/` の一覧系が、1000件を超えた分を黙って落とす**（PostgREST の既定の上限。
  アプリ側で範囲を指定していない）。利用者からは「登録したのに出てこない」に見える。
- `docs/failures.md` の append-only を機械で止めていない（2回破りかけている）。
- **squash マージ後にブランチを作り直す規則を、機械で止めていない**（4回違反している）。
- `auto-merge.yml` がイベントを取りこぼすと、全緑のPRが誰にも気づかれず止まる
  （塞ぎ方の候補は `docs/failures.md` 2026-08-06 に書いた）。
- **`main` の CI が赤いまま何日も気づかれないことがある**（今回3回連続で見落とした）。
  日次で main の CI 結果を見る仕組みが無い。
