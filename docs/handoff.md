- **CodeRabbit 指摘「集計ループの中間オーバーフロー」を修正**（コミット `ebc9a1b`）。
  `calcEstimate()` の `directCostSubtotal` / `taxable[category]` / `discountAmount` /
  `taxAmount` を素の `number` の `+=` で積んでおり、`assertSafeAmount()` がループ完了後にしか
  効いていなかった。行の中に負の金額（支給材控除）が正当に存在しうるため、期中の部分和だけが
  `Number.MAX_SAFE_INTEGER` を超えてから最終的に範囲内へ戻る入力を作ると、`Number.isSafeInteger`
  を通過するのに真値と1〜2円ずれる、という指摘。`node -e` で自作の反例（11回加算・10回減算）を
  作って実際に再現することを確認してから直した。
  集計を `BigInt` のまま積み上げ、`number` への変換は範囲を確認してから一度だけ行う
  `bigIntToSafeAmount()` に構造ごと変更。回帰テストも追加（`quantity=999137,
  unitPrice=999000251` を11加算・10減算する組み合わせ）。
- CodeRabbit が上記修正を再レビューし、「追加の問題なし」を確認済み（コメントで撤回・確認の
  やり取りをそのまま残してある）。
- 残っていた未解決スレッド2件（`.env.example` はすでに直っていたのに未クローズだっただけ、
  `home.test.tsx` の `renderToStaticMarkup` + 関数フォームアクションの指摘は実測で反証し
  CodeRabbit が指摘を撤回）を両方クローズ。
- `docs/failures.md` に、今回で完結した一連の浮動小数点対応（固定許容幅→ULP相対→BigInt化→
  安全整数の上限→集計ループのBigInt化、計5段階）を1件のログとしてまとめて追記した。
